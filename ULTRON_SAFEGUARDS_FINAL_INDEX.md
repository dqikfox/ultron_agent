5 CRITICAL NON-NEGOTIABLE RULES
================================

1. NEVER change ports without reading PORT_MAPPING_AND_SERVICES.md
   - Ports are interconnected
   - Changes affect multiple files
   - Requires testing and documentation

2. NEVER delete core files without understanding consequences
   - Core files: main.py, agent_core.py, brain.py, web_gui_server.py, api_server.py
   - System won't work if these are deleted
   - Always have backup first

3. ALWAYS test before deploying
   - Use 13-item verification checklist
   - Test on local machine first
   - Don't skip verification

4. ALWAYS backup before changing
   - File backup: Copy file with .backup extension
   - Git backup: git commit before changes
   - Timestamp backup: Include date in filename

5. ALWAYS document your changes
   - Add changelog entry
   - Include why, what, and how
   - Include rollback procedure

10-ITEM PRE-CHANGE CHECKLIST
=============================

Before modifying ANY code:
1. What file(s) will I change?
2. What port(s) are involved?
3. What service(s) will be affected?
4. Will startup sequence change?
5. Do I have dependencies documented?
6. Is there a backup ready?
7. Do I know how to test this?
8. Do I have a rollback plan?
9. Can I explain this change in 2 sentences?
10. Will I document this in changelog?

If you can't check all 10: STOP - Read documentation first

8-STEP SAFE CHANGE PROCEDURE
=============================

1. Read: Relevant safeguard documentation
2. Plan: Write down exactly what you're changing and why
3. Backup: Create backup (file or git commit)
4. Change: Make MINIMAL, FOCUSED changes only
5. Document: Add comments and changelog entry
6. Test: Run 13-item verification checklist
7. Verify: All tests pass, no errors
8. Commit: git add . && git commit -m "feat: description"

13-ITEM VERIFICATION CHECKLIST
===============================

After making a change:
1. Syntax: python -m py_compile file.py
2. Imports: All imports resolve
3. Ports: No conflicts, correct ports used
4. Config: Configuration reads correctly
5. Startup: ./run.bat completes without errors
6. GUI: http://localhost:8080 loads
7. API: curl http://localhost:5000/health responds
8. AI: Ollama responds to requests
9. Tests: pytest -m unit passes
10. Logs: No error messages in logs/
11. Backup: Can restore from backup
12. Rollback: Git rollback works
13. Documentation: All docs updated

All must pass before deployment
