# ULTRON Auto-Analysis Suggestion Schema

This document defines the JSON schema for suggestions generated by NIM (NVIDIA Inference Microservices) or other AI models during auto-analysis workflows.

## Schema Version
- **Version**: 1.0
- **Date**: September 20, 2025

## Purpose
The suggestion schema ensures structured, parseable output from AI models when analyzing ULTRON's codebase for improvements. This enables automated patch generation and application with safety checks.

## JSON Structure

```json
{
  "suggestions": [
    {
      "id": "string (unique identifier)",
      "module": "string (target module/file path)",
      "type": "string (refactor|update|optimize|add|remove)",
      "priority": "string (high|medium|low)",
      "description": "string (human-readable explanation)",
      "code_snippet": "string (the actual code change)",
      "file_path": "string (relative path to file)",
      "line_number": "integer (optional, target line)",
      "confidence_score": "float (0.0-1.0)",
      "risk_level": "string (low|medium|high)",
      "dependencies": ["array of strings (affected modules)"],
      "test_required": "boolean",
      "rollback_plan": "string (optional, how to revert)"
    }
  ],
  "metadata": {
    "analysis_timestamp": "ISO 8601 timestamp",
    "model_used": "string (e.g., 'nvidia-llama-3.1-70b')",
    "analysis_scope": "string (e.g., 'full_codebase' or 'utils/')",
    "total_suggestions": "integer",
    "estimated_effort": "string (hours or complexity level)"
  }
}
```

## Field Descriptions

### Suggestions Array
Each suggestion object represents a proposed code change.

- **id**: Unique identifier for the suggestion (e.g., "refactor_voice_error_handling_001")
- **module**: Target module name (e.g., "voice_manager", "utils.event_system")
- **type**: Type of change
  - `refactor`: Restructure existing code
  - `update`: Modify existing functionality
  - `optimize`: Performance improvements
  - `add`: Add new features
  - `remove`: Remove deprecated code
- **priority**: Implementation priority
- **description**: Clear explanation of the change and its benefits
- **code_snippet**: The actual code to be inserted/modified (escaped if necessary)
- **file_path**: Relative path to the target file
- **line_number**: Optional target line number for the change
- **confidence_score**: AI model's confidence in the suggestion (0.0-1.0)
- **risk_level**: Potential risk of the change
  - `low`: Safe changes (comments, minor optimizations)
  - `medium`: Functional changes with tests
  - `high`: Structural changes or new dependencies
- **dependencies**: List of modules that would be affected
- **test_required**: Whether automated tests should validate the change
- **rollback_plan**: Instructions for reverting the change if needed

### Metadata Object
Analysis context information.

- **analysis_timestamp**: When the analysis was performed
- **model_used**: Which AI model generated the suggestions
- **analysis_scope**: What part of the codebase was analyzed
- **total_suggestions**: Number of suggestions generated
- **estimated_effort**: Rough estimate of implementation time

## Usage Examples

### Example 1: Code Refactoring Suggestion
```json
{
  "suggestions": [
    {
      "id": "refactor_error_handling_001",
      "module": "voice_manager",
      "type": "refactor",
      "priority": "medium",
      "description": "Extract error handling logic into separate method for better maintainability",
      "code_snippet": "def _handle_voice_error(self, error):\n    self.logger.error(f'Voice error: {error}')\n    self._fallback_to_text_input()",

      "confidence_score": 0.85,
      "risk_level": "low",
      "dependencies": [],
      "test_required": true,
      "rollback_plan": "Revert method extraction and inline error handling"

  "metadata": {

    "analysis_scope": "voice_manager.py",

    "estimated_effort": "2 hours"
  }
}
```

## Implementation Guidelines

### For AI Models
When generating suggestions, always:
1. Use valid JSON format
2. Include all required fields
3. Provide realistic code snippets
4. Set appropriate confidence scores and risk levels
5. Consider dependencies and testing requirements

### For ULTRON Parser
When parsing suggestions:
1. Validate JSON structure
2. Check confidence scores against thresholds
3. Filter by allowed modules from config
4. Verify file paths exist
5. Assess risk levels before auto-application

### Safety Considerations
- Never auto-apply high-risk suggestions without manual review
- Always create backups before applying changes
- Run comprehensive tests after each change
- Log all auto-changes with rollback information
- Respect user configuration for auto-analysis settings
